## Предложения в базу знаний
- [target: skill:maverickframe-publish §Common errors | durable] Эндпоинт `/wp-json/wpvibe/v1/cli/run` молча отклоняет любую команду, содержащую `|` (shell_chars-гард), и не принимает пустое значение в `post meta update <key> ""`. Поэтому `rank_math_title` (в нём ` | Maverick Frame Studio`) ставится через `POST /wp-json/rankmath/v1/updateMeta {objectType:'post',objectID:<id>,meta:{rank_math_title:'…'}}`, а очистка меты — через `post meta delete <key>` (не `update … ""`). `db query` с INSERT/UPDATE может требовать ручного подтверждения.
- [target: skill:maverickframe-publish §Phase 6 | durable] На этом сайте Rank Math-мету можно писать без Chrome: `rank_math_focus_keyword` и `rank_math_description` — через cli `post meta update`; `rank_math_title` — через REST `/rankmath/v1/updateMeta` (он корректно проносит `|`). Возвращает 200, значение персистится.
- [target: skill:maverickframe-publish §Phase 4 | durable] REST `content.raw` отдаёт блочную ACF-разметку с HTML-спецсимволами в виде unicode-эскейпов (`<`, `>`, `&`, `"`) и литеральными `\r\n`. При строковой замене в `content.raw` ключи `MAP` должны совпадать с этими эскейп-формами, а не с сырыми `<`/`>`/`&`/`"`.
- [target: new: multilingual.md | durable] Polylang Pro через REST: перевод создаётся одним `POST /wp/v2/<type>` с полями `lang:'es'` и `translations:{en:<EN_ID>}` (работает для pages, services, success-stories, blog) — пост сразу языково связан. Шаблон страницы можно задать тем же запросом полем `template`.
- [target: new: multilingual.md | durable] Переводимые типы записей в Polylang на сайте: blog, services, solutions, success-stories, portfolio, team. CPT `gallery` НЕ переводимый — его категории/элементы языконезависимы и одинаковы на EN и `/es/`; ярлыки категорий локализуются PHP-картой в `gallery-items.php`, при этом `data-tab` остаётся `sanitize_title($en_title)`, иначе JS-фильтр перестанет находить блоки.
- [target: new: multilingual.md | durable] На фронте Polylang фильтрует запросы CPT по текущему языку: страница с листинг-шаблоном CPT (хаб блога/кейсов) автоматически показывает только посты текущего языка, поэтому ES-хаб пуст, пока нет ES-постов. Блок `trending` блога тоже идёт через `get_posts(post_type=blog)` и языкозависим (добавлен guard: секция скрывается при отсутствии постов).
- [target: new: multilingual.md | durable] ACF-Options ссылки меню и футера ведут себя по-разному. Топ-пункт хедер-меню — это `post_object` (фильтруется Polylang → при указании на EN-only страницу в ES-контексте резолвится в null и рендерится НЕкликабельным `<span>`; чтобы ожил — указывать на ES-перевод). Ссылки футера и подпункты меню строят URL через `get_permalink($id)` напрямую — это языконезависимо и резолвит любой ID (можно ставить EN-страницу как фолбэк там, где ES-версии нет).
- [target: CLAUDE.md §7 | durable] Хлебные крошки: переиспользуемый стилизованный класс — `ul.hero-block__breadcrumbs` (стили в `src/scss/new/blocks/breadcrumbs.scss`, самодостаточны: flex + стрелки-разделители). Стили `.single-team-hero__breadcrumbs` живут только в бандле страницы команды, поэтому переиспользование этого класса в другом месте (как было в галерее) даёт нестилизованный вертикальный список. На любом hero использовать `hero-block__breadcrumbs` и убедиться, что SCSS-бандл страницы импортирует `breadcrumbs.scss`; на белом/светлом hero переопределять разделитель на `arrow-right-breadcrumbs-black.svg`.
- [target: CLAUDE.md §7 | durable] Хелпер i18n `mfs_t($en,$es)` отдаёт ES только на `/es/` (проверяет `pll_current_language()==='es'`) — использовать для любых захардкоженных UI-строк в шаблонах, EN при этом не меняется. Даты карточек: `get_the_date('F j, Y')` остаётся английским без языкового пакета es_ES — испанские месяцы форматировать PHP-картой в `articles-item.php`, не полагаясь на пакет.
- [target: CLAUDE.md §12 | durable] При сборке ES-кейсов из EN-исходников: убирать хвостовой абзац-CTA «Want a similar result… Our team produces…» (он ссылается на EN `/services/`), убирать пустой блок `acf/team-items` (рендерит только eyebrow, т.к. у team CPT нет ES-членов), и переводить внутренние ссылки на услуги на `/es/servicios/<slug>/` там, где ES-страница услуги существует (для услуг без ES-версии оставлять EN `/services/`).
- [target: skill:maverickframe-publish §ACF field keys | durable] ACF-поля CPT `blog` (имена для cli/меты): Author = `author` (ключ `field_65510ea8792e0`, post_object на CPT `team`; Alexandr Kasperovich = ID 2016), Read Time = `read_time` (`field_65510ed1792e1`, хранить «6 min»), Hero Title = `hero_title` (`field_699862a857b49`), FAQ-репитер = `faq_items` с `faq_items_<n>_title` (`field_699851ecabd31`) и `faq_items_<n>_description` (`field_699851ecabd32`), ключ репитера `field_699851ecabd30`. Для каждого значения рядом ставить `_`-префиксную ссылку на field-key.
- [target: dev-environment.md | durable] Локальный mu-плагин `wp-content/mu-plugins/local-media-from-prod.php` переписывает URL `/wp-content/uploads` на `https://maverickframe.com`, чтобы локалка показывала прод-картинки без синка uploads. Он ДОЛЖЕН вешаться на фильтры URL вложений (`wp_get_attachment_url`, `wp_get_attachment_image_src`, `wp_calculate_image_srcset`), а не только на `template_redirect`/output-buffer — иначе ответы admin-ajax (Load more / сортировка на хабах блога и кейсов) сохраняют локальные URL и картинки дают 404. Файл LOCAL ONLY, в git темы не входит, на прод не деплоить.
