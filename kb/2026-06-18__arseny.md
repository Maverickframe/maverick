## Предложения в базу знаний
- [target: forms.md (new) | durable] `forms/amo.php` (обработчик лид-форм) НЕ имеет проверки окружения: он всегда шлёт POST в реальный amoCRM (pipeline 8408538, тег `maverickframecom`) с токеном из `forms/amo-credentials.php`, а этот файл синхронизирован из прод-снапшота и лежит и на локалке. Значит отправка любой формы С ЛОКАЛКИ создаёт настоящие прод-лиды. Строку `"Success"` `amo.php` печатает только после ответа amoCRM кодом 200–204, поэтому появление модалки «Gracias» в JS = реальный лид уже создан. Не тестировать форму на локалке без нужды; если протестировал — удалить тестовые лиды в amoCRM.
- [target: forms.md (new) | durable] Generic-capture в `amo.php`: читаются `Name`, `Phone` (или `WhatsApp`), `Email`, `title`, `Message` + UTM; ЛЮБОЕ другое POST-поле автоматически дописывается в `Message` лида (обрезается до 500 симв.). Поэтому новой лид-форме не нужен отдельный PHP-обработчик — достаточно добавить именованные поля. Обязателен телефон ИЛИ email, иначе обработчик возвращает `"Error"`.
- [target: CLAUDE.md §7 | durable] Значения из `wp_localize_script`, которыми JS строит URL к файлам темы (напр. `contacts.home_url` для POST на `…/forms/amo.php`), должны браться из `get_option('home')`, а НЕ `home_url()`: `home_url()` фильтруется Polylang и на испанских страницах возвращает `/es/`, из-за чего POST формы уходит на `/es/wp-content/...` и ловит 404.
- [target: CLAUDE.md §7 | durable] Общий JS контакт-форм `src/js/components/contacts.js` слушает submit на `window` (всплытие) и шлёт через fetch; модалка успеха показывается только при ответе ровно `"Success"`. Обработчик вызывает `phoneInput.closest('label')` — поэтому `input[type=tel]` ОБЯЗАН быть внутри `<label>`, иначе JS падает и success-модалка не появляется. Чтобы добавить свою валидацию — вешать submit-хендлер в фазе CAPTURE (он сработает раньше всплывающего) и при ошибке делать `stopImmediatePropagation()`. На форме контактов стоит `novalidate`, вся валидация — на JS со стилизованными `.cform__error`.
- [target: CLAUDE.md §2 | durable] Новый дизайн теперь покрывает и страницу Contacts (только ES, `/es/contacto/`): шаблон `templates/template-contacts.php`, партиалы в `components/new-design/contacts/`, отдельный Vite-бандл `contacts` (`vite.config.js` + `inc.vite.php` + импорт `contacts-phone.js` в `bundle.js`), `isNewDesign()` включает этот шаблон. Английская `/contacts/` остаётся на легаси-дизайне.
- [target: CLAUDE.md §7 | durable] Шаблоны со светлым hero должны передавать в хедер `'class' => 'header_white'`, иначе белое меню не видно на светлом фоне (грабля на `templates/template-services-hub.php`).
- [target: CLAUDE.md §7 | durable] На success-stories глобальное правило `.success-stories-page .review-item { color: #000 }` делает цифры рейтинга невидимыми на тёмном `hero-front`; фикс — `.hero-front .review-item { color: var(--white-color) }`.
- [target: CLAUDE.md §9 | durable] Повседневная работа с кодом идёт в ветке `multilang` (локальная отслеживает `origin/multilang`), а не напрямую в `main`. Поток: коммит в `multilang` → `git push origin multilang` → PR `multilang → main` → merge; именно merge в `main` запускает `deploy-staging.yml`. Грабля: `git push origin main` пушит ваш (отставший) ЛОКАЛЬНЫЙ `main` в удалённый `main` независимо от текущей ветки — он не несёт работу из `multilang` и обычно отлетает с reject. Использовать поток ветка+PR.
- [target: dev-environment.md | durable] Сборка Vite из песочницы Cowork: `node_modules` в LocalWP-маунте содержит macOS-бинарники и падает под Linux-песочником. Воркэраунд — скопировать `src/` + `vite.config.js` в `/tmp/b` (там установлены Linux-`node_modules`), запустить `npx vite build`, затем скопировать `build/assets/*` и `build/.vite/manifest.json` обратно в `build/` темы. (`build/` в gitignore; CI пересобирает при деплое.)
- [target: kb/schema-changelog.md | история] 2026-06-18 — локалка → PR (multilang→main): собран ES-хаб «Servicios» (`/es/servicios/`, перевод EN-страницы услуг: hero+мета+7 ACF-блоков, keyword/анти-каннибализация, связки меню/футер) и новая страница «Contacts» в новом дизайне (ES, `template-contacts.php` + `components/new-design/contacts/*`: hero, amoCRM-форма, connect-блок, FAQ, success-модалка; кастомный дропдаун кода страны + полный международный номер в скрытое `Phone`; клиентская валидация всех полей: имя/email/телефон E.164 6–15/сообщение 1000+счётчик/файл тип+15МБ/согласие; Vite-бандл `contacts`). Фиксы: `header_white` на services-hub; цвет цифр рейтинга на тёмном hero success-stories.
