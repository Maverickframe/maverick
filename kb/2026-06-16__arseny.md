## Предложения в базу знаний
- [target: dev-environment.md | durable] Перенос контента локалка↔прод при заблокированном cross-origin XHR — мост `window.name`: на одном origin `window.name = JSON.stringify(data)`, навигировать ТУ ЖЕ вкладку на другой origin, прочитать `window.name` (переживает кросс-доменную навигацию, держит мегабайты). Так дословно переносится `content.raw` + мета. Локальная БД — снапшот прода, поэтому ID постов и медиа совпадают: Polylang-связки ставятся по EN-ID, ссылки на картинки переживают перенос.
- [target: skill:maverickframe-publish §Common errors | durable] cli/run (`/wp-json/wpvibe/v1/cli/run`) принимает значения в двойных кавычках с пробелами, `<`, `>` (напр. `hero_title` с `<em class='mark'>…</em>`), но НЕ принимает значения с двойными кавычками `"` (одинарные кавычки вокруг значения он не группирует — ошибка «Usage», а `\"` не экранируется). Поэтому Schema JSON-LD (в нём везде `"`) ставится через FormData-POST на `wp-admin/post.php`, не через cli. `|` по-прежнему отклоняется → `rank_math_title` через `/rankmath/v1/updateMeta`.
- [target: skill:maverickframe-publish §ACF field keys | durable] ACF Schema-поле: имя `schema_org` (ключ `field_64ea0fc545b5a`), ставится через post.php FormData. URL внутри `@graph` строить сразу с прод-доменом (`https://maverickframe.com/...`) — тогда схема переносится с локалки на прод без правок.
- [target: skill:maverickframe-publish §Phase 5 | durable] У блог-поста ACF-поле `author` имеет дефолт (Alexandr Kasperovich, ID 2016, CPT `team`) → пост показывает автора даже при пустой мете. Сохранение через post.php (для schema) собирает поля из DOM и может обнулить выставленную cli мету `author` → ставить `author` ЯВНО ПОСЛЕ сохранения схемы. Профили авторов (CPT `team`) только EN → `author.url` в схеме и «Ver perfil completo» ведут на `/team/<slug>/`.
- [target: new: multilingual.md | durable] Перевод базовых слагов CPT — Languages → Strings translations, группа «URL slugs»: задать ES-значение для каждого базового слага (`services`→`servicios`, `success-stories`→`casos-de-exito`) и сохранить форму строк. Обычные страницы (галерея) переводят слаг сами (`galeria`), отдельной строки им не нужно. После сохранения `rewrite flush` не обязателен (Polylang применяет на лету), старые `/es/services/...` 301-редиректят на новые, EN-слаги не затрагиваются.
- [target: CLAUDE.md §7 | durable] Мега-меню Portfolio (`components/common/menu/menu-our-works.php`) берёт кейсы через `post__in => $our_works['cases']` + `posts_per_page => -1`. Если ACF-поле `cases` пустое, WP_Query ИГНОРИРУЕТ пустой `post__in` и возвращает ВСЕ success-stories (85+) — они попадают в HTML шапки на КАЖДОЙ странице (визуально свёрнуты вёрсткой → «скрытые» массивы ссылок, бьёт по внутреннему весу/crawl/Core Web Vitals). Правило: всегда страховать пустой `post__in` лимитом (в коде сделан fallback на 6 последних). ACF relationship (`cases`) через cli чисто не задать (сериализованный массив с кавычками) → лечить кодом либо курировать список в админке.
- [target: CLAUDE.md §7 | durable] Топ-пункт меню (`menu_items[_es]`) рендерится как дропдаун-`<span>` (игнорируя собственную ссылку `link`), если у него непустой счётчик `groups_links` ИЛИ keyname `our_works`/`resources`. Чтобы пункт стал обычной кликабельной ссылкой — обнулить счётчик `groups_links` (→ 0). keyname задаёт тип выпадашки: `company` → menu-big-links (Equipo/Contacto), `resources` → menu-resources.php, `our_works` → menu-our-works.php.
- [target: new: multilingual.md | durable] Выпадашка Resources (`menu-resources.php`) = иконка-ссылки из ACF `menu_resources[_es]` (title/description/icon/link) + АВТО-выдача последних 4 блог-постов (фильтруется по языку). Чтобы Resources появился в ES-меню, нужен топ-пункт `menu_items_es` с keyname `resources`; URL иконка-ссылок задаются в `menu_resources_es` (ES-пути). На /es/ компонент берёт `menu_resources_es`, если он непустой, иначе откатывается на EN.
- [target: CLAUDE.md §7 | durable] Проверка реального состояния прода под кэшем: канонический URL отдаёт закэшированный WP Rocket/CDN HTML, а запрос с неизвестным query-параметром (`?nocache=<ts>`) WP Rocket отдаёт свежим PHP — так проверяется, что код/контент реально задеплоен. `wp rocket clean` через cli/run заблокирован → чистить кэш в дашборде Rocket (+ WP Rocket).
